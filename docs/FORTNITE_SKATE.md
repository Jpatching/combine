# Fortnite + Skate contract

Fortnite supplies the selected island and its building, editing and destruction.
The existing native Skate simulation supplies movement, tricks and grinds.
The destination is the complete selected interactive island; static scenery or
a replacement movement model cannot satisfy it. MW2 combat and Synergy belong
to separate preserved experiences.

## Current experiment

[Issue #4](https://github.com/Jpatching/combine/issues/4) owns the selected
one-surface experiment, prerequisites, first-proof acceptance and current blockers.
Fetch that issue before resuming it. A visible marker driven by actual Skate output
is sufficient for the first proof; full animation, grinds and interactive-world
coverage follow. This staging does not reduce final acceptance.

Establish usable exact-client startup and reviewed native execution first. Game
files and reverse engineering are valid starting points; an official SDK or a
finished adapter is not required. Missing collision/rendering/Rust adapter code
is experiment work, not an automatic reason to reject a host.

Prefer in-process integration through the existing Skate Session. A separate
process needs evidence of a concrete constraint. Derive the adapter from inspected
interfaces; no universal framework or new public bridge API is selected. Combine,
Blender and any particular Fortnite version are optional.

## Final acceptance

- Explore the complete selected island using actual Skate movement, tricks and grinds.
- Build on foot, switch to skating, and ride/jump/grind the resulting surfaces.
- Editing changes collision to the new shape; destruction removes obsolete collision.
- Keep visible geometry, collision, controls and pose/camera output consistent;
  stop skating safely when valid collision or input ownership is unavailable.
- Recover, exit and reproduce after relaunch. Record island coverage, regional
  travel, load time, memory and frame times on identified Windows hardware.

Simultaneous building while skating is deferred. Preserve Fortnite world behaviour
rather than rebuilding it. Source checks, native execution, observed gameplay and
owner acceptance are distinct evidence claims.

## Boundaries and evidence

Preserve original installs and working builds; isolate trial copies and profiles.
Keep assets, converted data, identities, settings and raw private logs outside Git
and AI uploads. No DRM/anti-cheat bypass, new engine, universal merger, marketplace
or production launcher is authorized. Acquisition, launch, spending, outreach,
redistribution, deployment and release require task authority; this contract alone
does not grant it. Source licences do not establish asset or publisher rights.

The [handoff](HANDOFF.md) records retained evidence and recovery debt. The
[dated qualification](../research/results/2026-10-06-fortnite-adapter-qualification.md)
preserves investigation history and the original owner clarifications; its old
candidate ordering and tracker instructions do not select new work.
