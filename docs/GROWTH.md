# Help people discover and reproduce Combine

Observed 2026-10-05. These are researched recommendations and proposed repository
settings, not applied GitHub metadata, promotion or promised growth. A useful demo,
clear supported scope and successful onboarding are the intended reasons to star
or return. No measured Combine acquisition or retention results exist yet.

## Position the project accurately

Suggested repository description:

> Rust game mashup experiments with reproducible source and isolated player trials. MW2/Minecraft/Skate research; Fortnite + Skate-only integration in qualification.

Suggested README title: **Combine — reproducible game mashup experiments in Rust**.
Use phrases naturally in the introduction, experience table and reproduction links:
“game mashups”, “Rust”, “Skate 3”, “MW2”, “Minecraft” and “Fortnite + Skate”. Label
Fortnite as qualification and Synergy hit radius as unimplemented wherever relevant.
These are descriptive keywords, not evidence of search volume or ranking gains.

Proposed topics: `rust`, `game-development`, `game-modding`, `game-mashup`,
`skate-3`, `mw2`, `minecraft`, `experimental`, `reproducible-builds`.
`fortnite` may describe the planned integration if the description clearly states
its readiness. Check existing topics before applying; do not overwrite useful
ones. GitHub says relevant topics help people find and contribute to projects;
it does not promise ranking or star growth. [GitHub topic guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).

## Turn interest into a successful first experience

Lead the README with purpose, what exists, a quick reproduction path, limitations
and help/contribution routes. GitHub explicitly recommends those elements.
Our README now links the roadmap and reproduction guide; these edits are local,
not yet published. [GitHub README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).

Proposed next presentation work: an authorized, rights-reviewed short demonstration
of an exact tested build, plus a source-safe social preview image with the project
name, one clear outcome and experimental status. Link the demo to reproduction
and evidence rather than a nonexistent playable download. GitHub supports a
repository social preview for shared links; this is presentation advice, not an
algorithm claim. [Social preview documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview).

Make contributions approachable: explain the Rust/patch workflow, expose small
well-specified tasks, credit contributors and respond to reports. Keep the private
planning board as status authority; future public contributor issues must link to
an approved task rather than become a competing tracker. Review general source
licensing and contributor policy before describing all repository content as freely
reusable; Synergy's GPL attribution is already recorded. GitHub's community guide
recommends clear documentation, contribution guidance, beginner issues and a
responsive maintainer. [Building welcoming communities](https://opensource.guide/building-community/).

## A small pilot before broad promotion

Proposal for owner discussion: recruit a small opt-in group after one exact build
and its lawful-data prerequisites are ready. Ask players to follow the documented
setup, reach the promised outcome and repeat it after relaunch. Ask one contributor
to reproduce the source checks/build without private help. Record success/failure,
setup friction and build identity; agree counts and success thresholds before
running the pilot. Existing validation protocol can be reused. No outreach occurred.

After separately authorized promotion, share a truthful demo/devlog where game-modding,
skating and Rust communities permit it; invite useful feedback/contributions and
an optional star to bookmark progress. Avoid unrelated tags, star exchanges or
invented “fully working” claims. This channel recommendation is our inference,
not measured evidence of which community will convert best.

Measure views/clones/referrers alongside exact-build participant results, verified setup
success, repeat players and repeat contributors. GitHub traffic data covers a limited recent window, so
record dated observations rather than claiming lifetime conversion. Stars save
repositories; they are not counts of active players. Following accounts and
watching repository activity serve different interests. [Repository traffic](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository),
[discovery and following](https://docs.github.com/en/get-started/exploring-projects-on-github/discovering-projects-on-github),
[stars](https://docs.github.com/en/get-started/exploring-projects-on-github/saving-repositories-with-stars).

Next concrete step: finish source/export qualification and define the first hub's
readiness evidence on the existing wayfinding map. Metadata changes, public docs,
recordings, outreach, hosting and release remain separate authorized actions.

## Further SEO work for a future public hub

These are proposals for a later website slice, not a deployed hub:

- Give each experience a descriptive page title and URL, such as “Fortnite + Skate
  integration research | Combine” while unimplemented, or a setup title only
  after a real tested setup exists. Keep useful text in accessible HTML.
- Write actual setup/troubleshooting answers that people can search for, with
  required inputs, exact tested build and failure recovery. Link those pages from
  the experience catalogue with descriptive text, not isolated keyword lists.
- Publish an authorized exact-build demo with a unique title/description. A
  dedicated page where the video is the main content can support video indexing;
  an incidental README embed does not automatically qualify for video features.
- Once a site exists and publication is authorized, inspect indexing with Search
  Console. Track impressions/clicks as discovery evidence alongside player success;
  do not present visibility or stars as tested gameplay.

These recommendations apply Google's guidance to Combine; their effectiveness
has not been measured. Sources: [developer SEO guidance](https://developers.google.com/search/docs/fundamentals/get-started-developers),
[descriptive URLs](https://developers.google.com/search/docs/crawling-indexing/url-structure),
[SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide),
[video guidance](https://developers.google.com/search/docs/appearance/video).

Keyword stuffing and manipulative link schemes violate Google's spam policies.
Use accurate game names, practical content and earned relevant references rather
than purchased links or mass-generated pages. [Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies).
