## Spec

**P2: rail validation can admit geometry rejected later by host arithmetic.**
`patches/skate-standalone-v0.4.0.patch:3558` adds source
`skate/crates/skate-host/src/standalone.rs:174`. It checks original segment
squared distance in f64 and casts to f32. The pinned host instead constructs
f32 spline coefficients (-2 * delta, 3 * delta), reconstructs the endpoint,
then sums squared f32 chord components. Rounding can make that sum infinite
while the new guard remains normal and finite. Source locations:
`skate/crates/skate-host/src/grind_world/spline.rs:62` and `:132` at runtime pin
`f608f85e407ff1b7689d54a9aafdd16e95711ac4`.

The source-slice contract says "reject bad or excessive geometry before
asset/physics initialization"; the pinned evidence also promises rejection of
"unstable ... rail segment math". This case is accepted by World::validate and
can reach asset initialization before the host rejects its contact chord.
The existing host still rejects the invalid chord; no gameplay crash is claimed.
These are extreme finite coordinates accepted by the caller-selected limits,
not an observed ordinary-world gameplay failure.

Recommendation: validate the host's actual f32 spline/chord arithmetic before
asset access and add the public-boundary regression below. No fix was made.

```rust
use skate_host::standalone::{Limits, World, WorldError};

#[test]
fn host_overflowing_rail_must_fail_before_assets() {
    let end = [5.350520105300132e17_f32, 8.585608013744701e18_f32, 1.6318191816916599e19_f32];
    let reconstructed = end.map(|delta| (-2.0_f32 * delta + 3.0_f32 * delta) + 0.0_f32);
    let host_length: f32 = reconstructed.iter().map(|v| v.powi(2)).sum();
    assert!(!host_length.is_finite(), "witness must overflow pinned host math");
    let guard_length = end.iter().map(|v| (*v as f64).powi(2)).sum::<f64>() as f32;
    assert!(guard_length.is_normal(), "witness must pass current validation guard");
    let result = World::validate(
        vec![[[0., 0., 0.], [1., 0., 0.], [0., 0., 1.]]],
        vec![vec![[0., 0., 0.], end]], [0., 0., 0.], 0.,
        Limits { triangles: 1, rails: 1, rail_points: 2, geometry_bytes: 60, coordinate_magnitude: f32::MAX },
    );
    assert_eq!(result.unwrap_err(), WorldError::InvalidRail);
}
```
