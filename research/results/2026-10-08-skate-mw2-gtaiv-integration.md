# What Skate + MW2 needed, and what GTA IV needs now

Historical evidence from 2026-10-08. For current task authority and verdict, read
[the current context](../../docs/HANDOFF.md) and its linked live issue. Recommendations
below record this investigation; they do not select new work.

Researched 2026-10-08. Scope: pinned source comparison, not a new runtime trial. Upstream is `chasmlol/2010-rust-rewrite-mashup` at `f608f85e407ff1b7689d54a9aafdd16e95711ac4`; Combine source is `5689c012a78dd65f89e5d91ced430933cdc2f706`. Neither pin was moved. Local exported upstream source was inspected and its public collision/Session files were opened online. No assets, private coordinates, screenshots or logs are reproduced.

The key advantage of the MW2 Rust rewrite is direct access to the scene it owns: authoritative collision, player motion and rendering. Its Skate adapter passes that collision into the same Skate `Session` our GTA adapter already uses. GTA IV remains a separate existing engine, reached through CLEO natives. A better desktop controller helps operate tests; it does not supply trustworthy GTA collision. This is a source-based architectural inference, not a confirmed explanation of the live ground-query refusal. [MW2 adapter](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate.rs#L123-L144), [GTA mount](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/combine_skate.js#L25-L56).

## Concrete comparison

| Requirement | MW2 Rust rewrite | Current GTA IV #20 adapter |
| --- | --- | --- |
| Simulation | Embedded Skate crate; `Session::new` receives triangles, rails, spawn and heading. | Same untouched pinned Session, compiled into an in-process x86 plugin. No replacement simulation required. |
| Collision | Extracts map mesh, solid brushes and placed static-model collision; derives grind rails. | Samples 25 ground heights on an 8 m square and triangulates 32 faces; no rails. Central 7 m riding boundary. This represents a flat patch, not walls, props, traffic or the full GTA world. |
| Coordinates | Explicit axis rotation and 0.0254 conversion from map units to metres, reversed for presentation. | Equivalent axis rotation around mount origin; scale defaults to 1 GTA unit per metre and still needs runtime measurement. |
| Input | Reads the active Bevy gamepad, converts to Xbox input and feeds Session. | Reads XInput slot 0; allows only A/X push and left-stick steering for #20. Native loading and XInput slot 0 connection state have been observed; live push/steer response remains unverified. |
| Timing | Retained worker accumulates frame delta, caps backlog at 0.15 s and advances using Session's current period. | `GET_GAME_TIMER` drives fixed-period ticks; rejects gaps over 250 ms or more than 32 pending ticks. Runtime movement and interruption behavior remain unaccepted. |
| Presentation | Converts Session root, bones and camera into its own render state; hands player motion to external simulation. Includes soldier-bone retargeting and a board asset path. | Positions/headings a frozen stock ped and uses a simple chase camera. Does not display Skate bone animation or implement the full upstream camera. |
| Converted data | Owner's MW2 data plus locally converted Skate assets: animation banks, graphs/configuration, rig and board. | Private converted Skate data directory supplies Session. This candidate does not need MW2 map assets; it needs GTA native scene access and its selected patch. |
| Returning control | Stops external-motion ownership, suspends input and clears presentation while retaining the map Session. | Restores GTA player control, ped movement and owned camera, with a separate watchdog. These behaviors require live acceptance. |

Table sources: [collision extraction and units](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate/collision.rs#L4-L129); [Session loading and input/pose interface](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/physics/bridge.rs#L32-L185); [upstream timing/presentation/control](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate.rs#L214-L324); [upstream gamepad route](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate.rs#L375-L381); [asset setup and retarget components](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/docs/SKATE.md#L44-L80); [GTA surface/clock](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/src/connection.rs), [GTA Session calls](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/src/lib.rs), [GTA native presentation](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/combine_skate.js), [candidate limits and acceptance](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/README.md).

## How upstream avoids the current problem

Upstream does not use `GET_GROUND_Z_FOR_3D_COORD`: Session gets actual triangle geometry and the spawn is converted from its own player state. It still has to get collision winding, units, activation and pose mapping right. Its implementation explicitly reverses IW4 triangle winding, activates through Skate's teleport path and converts root/camera output back into host coordinates. These are concrete adapter responsibilities rather than proof that every upstream gameplay case works. [Collision](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate/collision.rs#L31-L57), [activation](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/physics/bridge.rs#L90-L109), [pose conversion](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate.rs#L302-L324).

The GTA script refuses near-zero or inconsistent ground before calling `COMBINE_SKATE_MOUNT`. Consequently, the supplied handoff's repeated first-guard refusal does not yet exercise Session creation, physics ticks or rendered Skate pose. Native return semantics, loading/query conditions, the selected surface and adapter assumptions remain questions for the diagnosis loop; this research establishes no defect in any of them. [Exact guard](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/combine_skate.js).

## Minimum next path for #20

1. Keep the existing bridge and build an unattended live feedback loop for the exact first-guard refusal, recording only the necessary redacted diagnostic signal. Verify the pinned native definition and results on the accepted baseline before changing the guard. A higher query origin is an experiment, not a presumed fix.
2. Obtain a trustworthy height signal and survey one visibly clear flat patch. Height sampling cannot detect visible obstacles between samples. Keep the bounded patch acceptance; full map extraction is not a prerequisite for this narrow task.
3. Once mounting actually succeeds, observe scale/axes/heading, push/steer response, timing, pose and usable camera. Repeat mount/dismount and the required restoration/failure cases, then obtain owner acceptance.

These steps follow the candidate's [declared acceptance](https://github.com/Jpatching/combine/blob/5689c012a78dd65f89e5d91ced430933cdc2f706/tools/gtaiv-skate/README.md). #21/#22 remain blocked on #20 acceptance. Scene-status publishing and input tests establish prerequisites; source compilation establishes linkage. Neither establishes visible skating. The complete upstream host-test suite remains unverified because the pinned host references missing `src/tests/map_startup.rs`, as recorded in the adapter README. No tests, launch, installation, permission changes or tracker mutations were performed for this research.

For a later, separately authorized larger GTA world, collision covering obstacles and changing scene geometry would be required, followed by rails and richer presentation as needed. The upstream `collision_builder`/`install_collision` interface is a useful existing extension point; Minecraft integration already rebuilds nearby block collision and installs it as the world changes. That is a source reference, not a ready GTA extractor or authorization to build one. [Existing streaming example](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/crates/render_anim/src/skate.rs#L153-L245).

## Follow-up: actual GTA IV native callers

HazardX's open GTA IV wrapper uses three float inputs plus a float output pointer, ignores the native return, and supplies several query-height strategies, including 1024 for highest ground. It also uses collision requests before environment loading. These support diagnostic probes, not a proven correction or acceptance of failed results. Its navigation-position helper does not survey collision. No primary evidence was found here establishing a dock/object exclusion or a Complete Edition defect. [Actual caller methods in World.cpp](https://github.com/HazardX/gta4_scripthookdotnet/blob/master/ScriptHookDotNet/World.cpp), [declaration](https://github.com/HazardX/gta4_scripthookdotnet/blob/master/ScriptHookDotNet/ScriptingOrig.h).

IV-SDK and IV-SDK .NET explicitly support only 1.0.7.0/1.0.8.0, so their source is a reference rather than a qualified replacement for our 1.2.0.59 runtime. GTA V/FiveM's similarly named boolean-returning native is not evidence for changing the GTA IV signature. [IV-SDK compatibility](https://github.com/Zolika1351/iv-sdk#iv-sdk), [IV-SDK .NET limitations](https://github.com/ClonkAndre/IV-SDK-DotNet#limitations).
