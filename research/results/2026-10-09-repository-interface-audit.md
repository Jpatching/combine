# What the public repositories actually supply

Source audit, 2026-10-09, for [#28](https://github.com/Jpatching/combine/issues/28). **These repositories contain substantial simulation and host-integration implementations, but the inspected source does not contain a complete adapter qualified for Combine's GTA IV 1.2.0.59 goal.** Reusing an implementation requires choosing its interface and supplying the missing host contracts; it does not require recreating everything. No architecture is selected here.

No builds, game trials, private game-data reads or runtime pin changes occurred. Some web pages returned cache misses; exact cloned public source supplied those observations.

## Simulation interfaces

The **pinned mashup** supplies an embedding interface: `Session::new(root, triangles, rails, spawn, heading)`, `activate`, `tick(Controls)`, `period`, `pose` and `suspend_input`. `Controls` carries Xbox-shaped buttons, triggers and sticks. `Pose` contains root and bone matrices, bone names, camera, velocity, tick and state. `collision_builder`/`install_collision` support replacing geometry. Construction loads converted gameplay, animation and graph data; it is not an asset-free engine. Its `collision_map` creates one material for supplied triangles, so that entry point does not itself preserve all host surface semantics. [Exact bridge](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/physics/bridge.rs).

The **current SK8 engine** has a different packaging boundary: `skate-game/Cargo.toml` declares standalone binaries; `main.rs` assembles input, physics, maps, presentation, setup and modding modules. Its inspected package is not the pinned `skate-host` Session API. The workspace depends on Bevy 0.18.1 with vendored rendering patches; the game uses statically built SDL3 and other graphics/asset dependencies. Moving to this revision would require an interface/dependency migration, not merely changing a pin. The pinned host separately declares Bevy 0.19 with limited features. [Current package](https://github.com/SK8-ENGINE/skate-3-rust-engine/blob/2e16697797c8358d16f747a8259354ff2921041a/crates/skate-game/Cargo.toml), [main](https://github.com/SK8-ENGINE/skate-3-rust-engine/blob/2e16697797c8358d16f747a8259354ff2921041a/crates/skate-game/src/main.rs), [workspace](https://github.com/SK8-ENGINE/skate-3-rust-engine/blob/2e16697797c8358d16f747a8259354ff2921041a/Cargo.toml), [pinned host manifest](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/Cargo.toml).

## Two concrete host implementations

**BullySkate** separates an x86 native host adapter from an x64 simulation worker. `src/skate_worker.rs` defines a fixed 6,184-byte shared-memory record with input samples, actors/vehicles, root, retargeted rider/board poses and camera. It observes parent lifetime and rejects nonfinite published outputs. `native/skate_worker.h` supplies mapping/events, process health and a kill-on-close job. These are reusable transport/lifecycle examples; their exact blocking/timing behavior still needs qualification before reuse. [Worker](https://github.com/Faiqie/BullySkate/blob/761c8def656b54481fa4bbbefba4156dd6300d34/src/skate_worker.rs), [parent](https://github.com/Faiqie/BullySkate/blob/761c8def656b54481fa4bbbefba4156dd6300d34/native/skate_worker.h).

Its `SkateHost::bully_visible` loads Bully geometry and a Jimmy bind/retarget file. `native_pose` emits 36 rider transforms; `native_board_pose` applies Bully-specific dimensions and orientation. Lua `restore` returns native controls/gravity/camera; game events call it. Thus it supplies an implemented host boundary in source, but its rigging, native layout and gameplay calls are Bully-specific. Rust manifests depend on a vendored rewrite and local runtime crate. [Runtime](https://github.com/Faiqie/BullySkate/blob/761c8def656b54481fa4bbbefba4156dd6300d34/skate-runtime/src/lib.rs), [ownership script](https://github.com/Faiqie/BullySkate/blob/761c8def656b54481fa4bbbefba4156dd6300d34/scripts/BullyMotion/main.lua), [manifest](https://github.com/Faiqie/BullySkate/blob/761c8def656b54481fa4bbbefba4156dd6300d34/skate-runtime/Cargo.toml).

**SkateGM** is an in-process Garry's Mod binary module with separate simulation and collision-builder threads, not an external worker process. Lua-facing `Load/Activate/Step/Poll/Stop` post work and consume poses. `engine.rs` wraps its modified local Session with installation, moving-collision and recovery methods. The worker limits repeated recoveries to three within ten seconds. A no-engine feature provides a fake simulation, so a stand-in pass cannot establish real skating. [Native module](https://github.com/the-schwilliam/SkateGM/blob/d392028e8581c74e003d5966f6826c144791f0bf/gm_skategm/src/lib.rs), [engine wrapper](https://github.com/the-schwilliam/SkateGM/blob/d392028e8581c74e003d5966f6826c144791f0bf/gm_skategm/src/engine.rs).

Server Lua `Enter/Leave` switches the native player between hidden/non-solid NOCLIP and normal WALK, restores weapons, and relocates through an unstuck check. Client Lua applies bone matrices and a `CalcView` camera. BSP parsing, Source geometry, Lua networking, player models and host hooks supply the remaining integration. The module's Rust 1.85 minimum and local `engine/` dependency do not qualify GTA or make those Lua APIs transferable. [Server ownership](https://github.com/the-schwilliam/SkateGM/blob/d392028e8581c74e003d5966f6826c144791f0bf/addon/skategm/lua/autorun/server/skategm_sv.lua), [render/camera](https://github.com/the-schwilliam/SkateGM/blob/d392028e8581c74e003d5966f6826c144791f0bf/addon/skategm/lua/autorun/client/skategm_cl.lua), [manifest](https://github.com/the-schwilliam/SkateGM/blob/d392028e8581c74e003d5966f6826c144791f0bf/gm_skategm/Cargo.toml).

## GTA host audit

LibertyCraft's `Boot` accepts 1070/1080; its build requires Windows x86 and IV-SDK. `EnterPuppet/ApplyPuppetState/LeavePuppet` implement control/camera ownership and mission-sensitive restoration. Direct ped movement is gated specifically to VERSION1080 with byte checks; otherwise it uses a native position call. Comments describe ambient-entity clearing on 1080: this is a reason to investigate gameplay preservation independently, **not evidence of the same failure on 1.2.0.59**. [Version gate](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/dllmain.cpp), [ownership/movement](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/Game.cpp), [build](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/CMakeLists.txt).

Its collision code uses `CWorld::ProcessLineOfSight`, region scheduling and separate object passes: reusable acquisition concepts, a native calling interface not qualified on Combine's baseline. CLEO documentation explicitly supports 1.2.0.59; its SDK provides `RegisterCommand`, float parameters and runtime-init callbacks. That establishes a documented plugin route, not sufficiency of every required native. [Collision source](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/Collision.cpp), [CLEO introduction](https://github.com/cleolibrary/CLEO-Redux/blob/bbf6773fe8cc1bfa95c73509a25928f97b0d8d13/docs/en/introduction.md), [SDK](https://github.com/cleolibrary/CLEO-Redux/blob/bbf6773fe8cc1bfa95c73509a25928f97b0d8d13/SDK/cleo_redux_sdk.h).

## Capability comparison on the retained GTA baseline

The two existing candidates share the GTA adapter and differ in where Session runs. The following comparison uses the preserved adapter at `c87e59471c34aff6ffcae5f23b8afc320ca6bd09`, its declared limitations and the dated issue evidence, rather than treating other games' APIs as GTA capabilities. [Adapter source](https://github.com/Jpatching/combine/blob/c87e59471c34aff6ffcae5f23b8afc320ca6bd09/tools/gtaiv-skate/combine_skate.js), [adapter/build contract](https://github.com/Jpatching/combine/blob/c87e59471c34aff6ffcae5f23b8afc320ca6bd09/tools/gtaiv-skate/README.md), [dated runtime verdict](https://github.com/Jpatching/combine/issues/20#issuecomment-6078907484).

| Required capability | Existing GTA candidates | What the other repositories change |
| --- | --- | --- |
| Load into GTA 1.2.0.59 | Documented CLEO route and attributed prior loading observations. | LibertyCraft's plugin is version-incompatible as supplied; porting is additional work. |
| Advance a skating simulation | Pinned Session interface; source/build and synthetic evidence, not original-game equivalence. | BullySkate/SkateGM demonstrate other embedding boundaries in source; latest SK8 is a migration candidate, not a transparent upgrade. |
| Display the resulting rider | `COMBINE_SKATE_VALUE` feeds root/heading into `SET_CHAR_COORDINATES` and a chase camera; no full Skate rider/board rendering. | Bully-specific retargeting and Source bone rendering show implementation patterns. Neither supplies the GTA rig/render implementation. |
| Preserve ordinary GTA gameplay | Explicit control/camera release and watchdog; complete walking/vehicle recovery remains unaccepted. | LibertyCraft's mission-aware ownership and documented 1080 movement side effects identify useful review cases. Their presence does not prove a defect on 1.2.0.59. |
| Supply world interaction | A bounded sampled floor, not an ordinary-city scene representation. | Alternative acquisition exists in source, but GTA-version compatibility and Skate suitability remain unqualified. |
| Meet timing and recover from failure | In-process and optional worker implementations; dated partial trials. | Alternative process patterns exist. Neither proves lower latency, safer recovery or less effort on our baseline. |

## Decision-changing next check

**The audit does not justify replacing the current candidates.** This is a recommendation to preserve the comparison baseline, not a selection of the final architecture. Directly copying LibertyCraft or simply updating the SK8 pin would introduce identifiable compatibility/interface work. Reusing transport, retargeting and ownership patterns selectively is a credible option, but savings have not been measured.

The next conversation should agree the first convincing proof against this table: which reconstructed-Skate behavior, visible presentation and retained GTA behavior must appear together for the route to be worth continuing? A flat-floor proof can test a limited interaction; it cannot stand in for acceptance of ordinary-city integration. Original Skate equivalence would require a separate reference comparison and cannot be assumed from reused assets.

Then write one bounded prototype brief whose possible outcomes select or reject a route. A host-control/presentation proof can test integration without developing a new scene acquisition system; a fixed-input Session comparison can test simulation behavior without GTA; geometry acquisition is appropriate only when its gap changes the route decision. State the exact baseline, observations and pass/stop criteria before runtime work. This audit does not establish which of those risks is largest, so none is selected by familiarity with the current mount failure.

The source audit closes the question of whether the cited repositories automatically supply everything needed: **they do not establish that**. It leaves specific host integration and behavioral evidence gaps, rather than a requirement to recreate the simulation or replace the entire architecture. No builds or runtime trials were performed, and #20's separate collision-research prerequisite remains in force if that research is selected.
