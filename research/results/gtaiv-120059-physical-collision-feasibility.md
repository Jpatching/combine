# GTA IV 1.2.0.59 physical collision feasibility

Source-only report for issue #32, parent #28 and gameplay #20; 2026-10-09. **Verdict: requires-local-proof.** Public source contains a concrete GTA IV physical `.wbn` reader. This makes a bounded static-scene alternative credible enough to investigate, but establishes neither complete city coverage nor compatibility with the owned 1.2.0.59 installation. No inspected implementation supplies a qualified loaded-collision traversal for that version. Preserve the existing candidates and pin; no runtime implementation is proposed for acceptance here.

### Actual reader and implemented limits

**GTA4Unity / vendored RageLib, revision `c107e46cf8ab4e3d42f9c0bf685f80bb732a3609`:** [CollisionFile](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Collision/CollisionFile.cs) reads a bounds resource's system-memory block, masks tagged pointers, reads the root bound type, and dispatches geometry/BVH/box, sphere/capsule or composite. Unsupported root types yield empty arrays. This is physical-bound parsing, not WDR render-mesh extraction. It explicitly describes `.wbn`; it does not establish a general WBD dictionary reader. [ResourceFile](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Common/Resources/ResourceFile.cs) decompresses resource data after a strict magic check; [ResourceType](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Common/Resources/ResourceType.cs) distinguishes bounds (`0x20`) from models/textures. Those checks are format checks, not an executable-version qualification.

[PhBoundGeometry](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Collision/PhBoundGeometry.cs) decodes signed 16-bit triples using per-axis unquantization factors and a bounding-box center, then maps RAGE coordinates to Unity. It reads 32-byte polygon records containing normal components, an area field, four packed vertex indices and neighbours. [PhPolygon](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Collision/PhPolygon.cs) masks indices with `0x7fff`, infers quads from the fourth index and exposes a material index from the area's low byte. Its comments claim validation against one named WBN and GTAIV constructor/decompiler lines; these are creator assertions, not reproducible evidence of 1.2.0.59 compatibility. The unsafe loops do not visibly validate complete vertex/polygon buffer spans before dereferencing.

[PhBoundComposite](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Collision/PhBoundComposite.cs) lists current/last matrix pointers in comments, but only reads the child-pointer array and counts. It neither applies those matrices nor recursively processes composite children. Sphere/capsule children become separate primitives. [BoundType](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/RageLib/Collision/BoundType.cs) includes additional geometry types that the dispatch does not implement and explicitly warns that IV values differ from GTA V. A box is sent through geometry parsing; success for every box layout is not proved.

[CollisionBuilder](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/IVUnity/CollisionBuilder.cs) selects `.wbn` files, parses all of them on a worker, merges geometry vertices/polygons, reverses triangle indices for Unity, and creates static colliders at zero translation. It ignores `Primitives`, skips geometry with missing arrays, silently catches file exceptions, and yields collider construction after an elapsed 12 ms check. This demonstrates a concrete consumption path but not a safe bounded streaming contract: a final ready tag can coexist with skipped files, and the yield check does not bound a single large construction operation. The reader is therefore a reference for audited decoding, not a converter to run unchanged.

The [GTA4Unity README](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/README.md) targets Unity 6 on Windows and names Complete Edition, Steam or EFLC installations without an exact 1.2.0.59 test. Its status text says no physics/gameplay yet even though collision-building source is present; rely on source presence, not interpret that inconsistency as a successful play test. Repository [license](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/LICENSE) contains GPL version 3; inherited RageLib's ResourceFile header explicitly grants GPL-3.0-or-later. New collision files lack individual grant/version notices, so preserve the repository license and resolve per-file terms before reuse. Source licensing does not grant rights to GTA assets or publisher content.

### Loaded structures, sampled surfaces and false substitutes

**IV-SDK, revision `dddbd3f54b146bdb3a9852809e48e5cb169af3cd`:** the [README](https://github.com/Zolika1351/iv-sdk/blob/dddbd3f54b146bdb3a9852809e48e5cb169af3cd/README.md) explicitly supports only EFIGS 1.0.7.0/1.0.8.0 and says other versions differ substantially. The [license](https://github.com/Zolika1351/iv-sdk/blob/dddbd3f54b146bdb3a9852809e48e5cb169af3cd/LICENSE) is GPL version 3. Its [phBound definitions](https://github.com/Zolika1351/iv-sdk/blob/dddbd3f54b146bdb3a9852809e48e5cb169af3cd/include/phBound.h) provide mostly padding and size assertions, not polygon enumeration. [CEntity](https://github.com/Zolika1351/iv-sdk/blob/dddbd3f54b146bdb3a9852809e48e5cb169af3cd/include/CEntity.h) separates placement/matrix, drawable and physics-instance pointers. This is evidence that transform/render/physics identities are distinct, not a usable CE bound walker. No reviewed locking, reference-lifetime or streaming-store traversal contract for 1.2.0.59 was established.

**LibertyCraft, revision `0fe0f2c9aae2ba974cb077e282b091a38f1ca48f`:** [boot code](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/dllmain.cpp) gates 1070/1080. [Rays](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/collision/Rays.h) calls native line queries on the game thread and documents hit semantics as measured on 1.0.8.0; static flags exclude vehicles and movable objects. [Objects](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/asi/src/collision/Objects.h) uses model bounds/axes and separate object sampling. [dump_collision.py](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/tools/dump_collision.py) maps the existing live collision ring and decodes produced triangles/voxels; it does not open IMG/WBN/WBD assets. Its root [MIT license](https://github.com/mrborghini/libertycraft/blob/0fe0f2c9aae2ba974cb077e282b091a38f1ca48f/LICENSE) applies to LibertyCraft source, while IV-SDK has its own GPL terms; an MIT root does not relicense that dependency. None of these sources is a drop-in 1.2.0.59 physical extractor.

**Excluded representations:** [CodeWalker README](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/README.md) describes GTA V `.ybn` collision separately from render formats; this does not establish IV `.wbn` compatibility. The [webmap navmesh reader](https://github.com/luckeyfaraday/gta4-webmap/blob/0cd9261b8834f2868961fc11bf75eeba8958756a/extractor/NavmeshExport.cs) exports pedestrian walkable footprints and explicitly leaves tile Z minimum undecoded, obtaining heights elsewhere. Navigation cannot supply walls, undersides, thin barriers or collision normals. Render triangles likewise do not establish which surfaces GTA physically blocks. Neither is accepted as physical collision merely because it produces polygons.

OpenIV's primary [collision-viewing/openFormat announcement](https://openiv.com/?p=240) was identified, but retrieval failed (web fetch 502; direct TLS certificate expiry). A search excerpt is not enough to audit its exporter, exact release revision, license, transform semantics or CE behavior. OpenIV is an unresolved candidate, not a verified reader in this report; no binary or game data was downloaded.

### Pinned Skate consumer

At `f608f85e407ff1b7689d54a9aafdd16e95711ac4`, [Session bridge](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/physics/bridge.rs) accepts `Vec<[[f32; 3]; 3]>` triangles and `Vec<Vec<[f32; 3]>>` rails in `Session::new`, supplies `collision_builder().build(triangles, rails)` for off-simulation preparation, and `install_collision(PreparedCollision)` to replace collision/grind state. The source describes replacement as effective from the next tick. This is a whole-world replacement seam, not a GTA object-ID or per-region mutation API. `collision_map` assigns one material, surface zero and no native edge metadata; supplied rails are open polylines without native metadata, and doors are empty. GTA material indices and polygon neighbours do not automatically retain their original semantics through this interface.

[physics setup](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/physics.rs) documents map spawn as the wheel-ground anchor in native Y-up metres. [collision compiler](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/skate/crates/skate-host/src/skate_world.rs) uses positions directly, welds vertices at 1 mm, derives cross-product normals, rejects invalid triangle normals, and marks portable faces one-sided. It reconstructs adjacency and explicitly treats triangle diagonals as adjacency, not authored ledges. This makes winding and quad splitting meaningful; polygon availability alone does not establish grindable rails. The mashup's [Apache-2.0 license](https://github.com/chasmlol/2010-rust-rewrite-mashup/blob/f608f85e407ff1b7689d54a9aafdd16e95711ac4/LICENSE) is separate from reader licensing and game-content rights.

## Source inference

### Geometry, placement and freshness contract

The minimum data flow is **owned physical bound → audited RAGE-space vertices/faces → correct instance placement → declared Skate-space triangles → existing Session builder/install**. It does not require a new engine. Applying a render WPL placement to every WBN would be unsafe: GTA4Unity's static builder places its decoded WBN colliders at identity, whereas its composite parser names but omits child matrices. Distinguish a world-space static bound from a reusable local bound and record that classification per resource. For a genuinely local child, apply child/composite and entity transforms exactly once, including scale and pivot/centroid conventions. WPL/render association alone is not proof of collision placement. Interior parent/child composition, hashed WBD associations and episode/patch overrides need separate verification.

The inspected [coordinate helper](https://github.com/Infinity-Loops/GTA4Unity/blob/c107e46cf8ab4e3d42f9c0bf685f80bb732a3609/Assets/Scripts/IVUnity/RageCoordinates.cs) implements RAGE Z-up to Unity Y-up as `(-x, z, -y)`, with stored-quaternion handling. Its inverse can recover RAGE coordinates from this reader's already-swizzled output. Do not swizzle a second time blindly or copy its Unity winding reversal into Skate. For a declared GTA-to-Skate linear map A, compute transformed points, derive the normal from their cross product, and correct vertex order when the transform reverses orientation; transform original normals with inverse transpose when nonuniform scale exists. Quaternion/matrix conventions must be checked against a rotated landmark rather than trusted from comments. Skate's Y-up metres are source-documented; GTA's physical unit scale and the retained adapter's exact orientation still require local calibration. Proposed 1 GTA unit = 1 metre is a hypothesis, not a proved CE measurement.

Split each valid quad into two triangles consistently with the polygon's cyclic boundary and normal. Reject malformed, degenerate, nonplanar or ambiguously indexed cases until their physical meaning is understood. Preserve seam welding without accidentally joining nearby distinct layers. Do not replace unsupported sphere/capsule/curved shapes with arbitrary boxes while claiming original fidelity; report them as unsupported or separately justify a bounded approximation. Retain materials/neighbours as private diagnostic metadata even though the audited Session entry point drops them.

File existence does not prove current collision activation. A privately decoded static tile may persist after GTA streams it out, and an offline source may not reflect scripted variants or current doors. A loaded walker would need exact-version type/layout validation, a safe copy under native lifetime protection, and an activation/generation snapshot; never retain native pointers in the worker. Proposed region states are unavailable, validated-empty, ready and stale. A skipped file or unrecognised bound must be unavailable, not empty. Carry provenance, coverage envelope and generation through off-thread building; reject stale build completion and install at a safe simulation boundary. Aggregate all valid nearby regions before whole-world replacement, or replacement can remove adjoining support. Coverage must extend beyond the rider's travel plus measured acquisition/build latency; pause/refuse ownership on unavailable coverage under the existing safety contract.

Moving traffic and doors require current instance transforms, shape/fragment changes, deletion tracking and invalidation of both old and new occupied regions. Static file extraction cannot supply their current pose, opening state, damage or velocity. The pinned seam accepts geometry snapshots rather than moving rigid bodies: repeated full replacement might represent position, but does not prove moving-platform friction, contact velocities, continuous collision or crush behavior. Keep those requirements explicit and separate from the static proof. An inspected old-version object sampler is useful prior art, not CE readiness.

### Comparison against native line-query reconstruction

These are derived expectations from the inspected decoder, Session seam and LibertyCraft query source, not benchmarks or conclusions of independent issue #31.

| Criterion | Physical files / loaded bounds | Native queries and reconstruction |
| --- | --- | --- |
| Acquisition fidelity | Can preserve authored thin surfaces, slopes and stacked layers without sampling spacing error. Still loses unsupported shapes, transforms, margins/material semantics or inactive variants if decoding is incomplete. | Measures host-active collision at query locations. Reconstructed triangles can bridge gaps or miss thin features/undersides; filters, one-sided hits and near-face behavior must be qualified. |
| Runtime cost | Files permit private predecode/cache and bounded nearby selection; cost moves to I/O, decompression, memory, acceleration building and snapshot replacement. Loaded extraction adds safe game-thread copy/locking. The inspected all-WBN builder is not a nearby streaming implementation. | Requires budgeted game-thread probes plus reconstruction and the same Skate compilation/replacement costs. Incremental sampling spreads cost but increases completion latency. |
| Host coupling | Offline decoding avoids native call/layout dependence for static data, but still needs exact install manifest, placement and activation correlation. Loaded walking depends deeply on CE layouts and lifetimes. | Needs exact CE callable interface, flags/results and thread contract; native engine owns shape decoding and active placement. |
| Verification effort | Byte spans/types, decode correctness, every required transform/primitive, semantic omissions, static activation, then Session contacts and freshness. Higher initial format burden; no measured effort estimate. | Qualify call contract, repeatability and timing, then coverage/reconstruction quality, Session contacts and freshness. Existing 1080 implementation offers more acquisition prior art, not CE proof. |

Both need a local truth comparison and moving-object work. Physical geometry is a credible **static candidate**, not yet a superior complete city solution. Prefer the bounded WBN proof over implementing a loaded walker from padding-only SDK definitions; preserve native queries as the comparison/oracle candidate. No universal adapter, pin migration or full-city export is authorized.

**One proposed bounded scene proof, not work executed or authorization to launch:** on the owner's retained offline Windows GTA IV 1.2.0.59 installation, select one fixed 20 m × 20 m static scene containing a floor/slope, vertical wall, overhang with clear space underneath and a thin barrier. 3. Under separate local proof authority, privately feed the resulting triangles to the **real pinned Session**, using its existing owned converted Skate data. Exercise fixed-input floor/slope support, wall blocking, travel under the overhang and thin-barrier contact. Rails may be empty: this proves static collision only. Do not add a fabricated rail to turn a contact pass into a grind claim.
4. Build/install the same scene via the audited replacement seam, then deliberately deliver an older generation after a newer one and mark a neighbouring region unavailable. Require stale completion rejection, no loss of valid adjacent support and refusal/hold before crossing unavailable coverage. Repeat the unchanged-scene install three times to expose seams/contact discontinuities. Future GTA observation remains without Skate ownership transfer; this is not mount/ride/dismount acceptance.

Proposed thresholds to lock before execution: physical agreement within 0.02 m at declared floor/wall/underside checkpoints, finite normals with the intended one-sided orientation, no penetration beyond 0.02 m in the fixed-input barrier checks, at most 100,000 triangles and 64 MiB of private decoded/prepared scene payload, game-thread acquisition/copy/install work at most 2 ms per host tick, and a prepared snapshot within 100 ms for this bounded scene. These are provisional engineering gates, not published performance facts; the owner/local coordinator must justify them against baseline frame time, skating speed and thin-feature clearance before the proof. No automatic relaxation after failure. Measure peak/percentile acquisition, build, install and Session tick times separately from file preparation time.

**Reject/stop** on unknown layout, unsafe resource spans, missing child transforms, unsupported required shapes, unexplained scale/winding, inconsistent physical oracle, mixed floor/ceiling, lost barrier, unavailable-as-empty, stale installation, budget/cap breach, contact discontinuity or host instability. A pass supports only this static scene and this pinned Session path. Traffic, doors, grind semantics, materials, streaming during riding and owner gameplay acceptance remain separate claims.
